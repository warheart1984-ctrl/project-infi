## 1. Purpose

To define the structural architecture of learning within CCALF, including layers, domains, lifecycle, and maturity levels.

## 2. Learning Layers

Each domain must map its content and evidence to the following layers:

### 100.1 Foundations

Core concepts, terminology, and primitives.

### 100.2 Standards

Industry, regulatory, and constitutional standards relevant to the domain.

### 100.3 Reference Architectures

Canonical models, diagrams, and governed structures.

### 100.4 Implementations

Hands-on practice, labs, projects, and applied engineering.

### 100.5 Evidence

Documentation, reflections, artifacts, and portfolio items.

## 3. Learning Lifecycle

Every domain follows the CCALF lifecycle:

**Discover → Learn → Understand → Practice → Build → Evaluate → Document → Govern → Teach → Steward**

Each phase must be explicitly mapped to domain-specific activities.

## 4. Learning Domains

Domains are independent specifications (500-series) that instantiate the curriculum architecture.

## 5. Maturity Levels

Competency is measured using the CCALF maturity model:

| Level | Title |
|-------|-------|
| L0 | Awareness |
| L1 | Literacy |
| L2 | Practitioner |
| L3 | Engineer |
| L4 | Architect |
| L5 | Steward |

Each domain must define criteria for each level.

## 6. Interfaces

- Curriculum → Evidence
- Curriculum → Conformance
- Curriculum → Governance

These interfaces must be explicitly defined in each domain specification.
