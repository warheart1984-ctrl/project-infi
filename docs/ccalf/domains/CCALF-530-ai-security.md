> **Honesty tag:** These documents are **declared/adopted framework specs**. They do not claim runtime enforcement inside host product engines unless a separate implementation and tests prove otherwise.

## 1. Domain Mission

To define the knowledge, architectures, evidence, and stewardship required to secure AI systems across their lifecycle, ensuring confidentiality, integrity, availability, and constitutional governance.

## 2. Domain Layers

### 530.1 Foundations

- Threat models
- Attack surfaces
- AI system components
- Constitutional security primitives

### 530.2 Standards

- NIST AI RMF
- ISO/IEC 27001, 27005
- OWASP ML/LLM Top 10
- CIEMS constitutional security invariants

### 530.3 Reference Architectures

- Secure model pipeline
- Constitutional threat chain
- Evidence-backed security controls
- Secure inference architecture
- Governance-aware monitoring

### 530.4 Implementations

- Adversarial testing
- Secure model deployment
- Constitutional guardrails
- Evidence-backed mitigations
- Replayable security audits

### 530.5 Evidence

- Threat models
- Attack simulations
- Security architecture documents
- Mitigation evidence
- Stewardship reflections

## 3. Domain Lifecycle Mapping

**Discover → Learn → Understand → Practice → Build → Evaluate → Document → Govern → Teach → Steward**

## 4. Domain Maturity Criteria

| Level | Criteria |
|-------|----------|
| L0 | Awareness of AI security risks |
| L1 | Literacy in threats and standards |
| L2 | Practitioner of secure AI components |
| L3 | Engineer of secure AI systems |
| L4 | Architect of governed AI security ecosystems |
| L5 | Steward of constitutional AI security |

## 5. Domain Governance Rules

- All security evidence must be reproducible
- All mitigations must map to constitutional principles
- Steward review required for major changes
